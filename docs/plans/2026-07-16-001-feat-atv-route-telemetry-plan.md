# Plan: T9 — `/atv` route telemetry writer (`atv-route-log`)

- **Status:** Ready to implement (TDD)
- **Type:** feat
- **Date:** 2026-07-16
- **Branch:** `feat/atv-router` (lands in PR #62 before merge)
- **Origin:** Follow-up #3 from the `/atv` router build. The router `SKILL.md`
  *documents* route telemetry (`~/.atv/analytics/routes.jsonl`, OTel-shaped,
  intent+target only) but there is **no writer** — the LLM is currently told to
  append the JSONL line itself. That is the exact fragility this task fixes:
  format correctness and the no-raw-text PII guarantee should not depend on the
  model getting it right every turn.

## Problem

Plan task **T9** (from `docs/research/gstack-router-atv-plan.md`, surfaced by CEO
E1 + Security §3): the `/atv` router must log each route to a local, OTel-shaped
JSONL file so usage and mis-routes can be measured — **without ever recording the
user's raw request text** (PII/secret safety).

Today the router skill instructs the model to write the line. Two risks:

1. **PII leak** — nothing structurally stops raw request text from landing in the
   log; it relies on the model remembering the rule.
2. **Format drift** — hand-written JSONL from an LLM is not guaranteed to be a
   parseable, consistent OTel shape.

The fix mirrors the `atv-config` shim already shipped this PR: a tiny,
zero-dependency Node writer with a **fixed schema**, called by the skill.

## Decisions (locked via /plan-eng-review)

- **D1 — Fixed schema, no free-form field.** `atv-route-log.js` accepts ONLY
  named fields (`--intent`, `--routed-to`, `--outcome`). There is no `attributes`
  passthrough and no free-form field, so the user's raw request sentence is never
  recorded (the caller-supplied tokens are newline-stripped and 64-char capped).
  This is the reason the shim beats LLM-driven logging.
- **D2 — Skill calls the shim.** Router `SKILL.md` runs
  `node .github/hooks/scripts/atv-route-log.js --intent <cat> --routed-to <skill>
  [--outcome <o>]` after routing. The LLM only supplies two short classifier
  tokens it already computed. Matches how the skill invokes `atv-config.js`.

## Decision: stack & architecture

Same conventions as `atv-config.js` / `lfg-state.js` / `observe.js` (the existing
ATV Node hook helpers): `"use strict"`, `node:`-prefixed requires, pure exported
functions + `require.main === module` CLI guard, **zero new dependencies** (Node
is already a baseline hook dependency).

```
 router SKILL.md  ──runs──▶  atv-route-log.js  ──append──▶  ~/.atv/analytics/routes.jsonl
    (2 tokens)                 (fixed schema)                 (OTel-shaped, one line/route)
                                    │
                               drops/ignores any
                               unexpected field  ──▶  raw text can never enter
```

### Record shape (OTel-shaped, one JSON object per line)

```json
{
  "name": "atv.route",
  "timestamp": "2026-07-16T06:12:00.000Z",
  "attributes": {
    "intent_category": "code-review",
    "routed_to": "ce-review",
    "outcome": "invoked"
  }
}
```

- `name` — constant `"atv.route"` (the OTel span/event name).
- `timestamp` — ISO-8601 UTC, generated by the shim (not passed in).
- `attributes.intent_category` — a short classifier token (e.g. `code-review`,
  `build`, `security`, `no-match`). Free-form string but **length-capped** (see
  sanitization) so it can't smuggle a sentence.
- `attributes.routed_to` — the target skill name, or `emit:lfg` / `no-match` /
  `control:off` etc. (the same target vocabulary as the routing fixtures).
- `attributes.outcome` — one of `invoked` | `emitted` | `suggested` | `no-match`
  | `control` (default `invoked`). Distinguishes an actual invoke from an
  emit-and-stop handoff or a suppressed (PROACTIVE=false) suggestion.

### Path + isolation

- Default file: `~/.atv/analytics/routes.jsonl` (dir created 0700, file 0600 —
  same posture as `atv-config`).
- **`ATV_CONFIG_HOME` override honored** (reuse the SAME env var `atv-config.js`
  already uses) so tests never touch the real home dir and both shims stay
  consistent. File resolves to `$ATV_CONFIG_HOME/analytics/routes.jsonl` when set.

### Sanitization (the PII guarantee, enforced in code)

`intent_category` and `routed_to` are each:
- coerced to string, trimmed;
- **length-capped at 64 chars** (a classifier token is short; a request sentence
  is not — the cap is the structural defense against text smuggling);
- newline-stripped (one record = one line, always parseable).

`outcome` is validated against the fixed enum; anything else falls back to
`invoked`. There is no code path that accepts or writes an arbitrary field.

## What already exists (reuse, do not rebuild)

- `atv-config.js` — the shim pattern (env override, atomic-ish write, 0600/0700,
  exported pure fns + CLI guard). `atv-route-log.js` mirrors it; do not invent a
  new convention.
- `observe.js` — the JSONL `appendFileSync` precedent (`.atv/observations.jsonl`).
- Router `SKILL.md` telemetry section — already documents the intent; T9.8 swaps
  prose for a concrete command.
- Routing target vocabulary — the fixtures already define `routed_to` values
  (`emit:lfg`, `no-match`, `control:off`, skill names); reuse them, do not
  redefine.

## NOT in scope (deferred, with rationale)

- **Any network/OTel exporter.** Local OTel-*shaped* JSONL only; a real
  OpenTelemetry SDK spends an innovation token on plumbing for ~10% more value
  (CEO §NOT-in-scope). Anyone with a collector can tail/forward the file.
- **Log rotation / retention.** The file is append-only and local; rotation is a
  follow-up only if it ever grows enough to matter.
- **Reading/analyzing the telemetry** (a `/atv stats` view). Separate feature;
  T9 only writes.
- **T7 `/investigate` debug skill and T8 `/lfg` auto mode** — separate plans, per
  the scoping decision. Not this task.

## Failure modes (new codepath)

| Failure | Test? | Error handling? | User sees? |
|---|---|---|---|
| Unwritable `~/.atv/analytics/` | ✅ T9.5/T9.7 | ✅ try/catch → false | Nothing (routing proceeds) |
| Malformed CLI args (missing field) | ✅ T9.6 | ✅ write nothing, exit 0 | Nothing (routing proceeds) |
| Oversized intent token (text smuggle) | ✅ T9.3 | ✅ 64-char cap + newline strip | N/A (never logged) |
| Concurrent appends (two sessions) | — | `appendFileSync` is a single syscall per line; interleave-safe for one-line records | Nothing |

No failure mode is both silent AND unhandled — telemetry is best-effort by
design and must never block a route.
